# 🚀 D4UC 구글 코랩(Google Colab) 전용 가이드 (Cloud Edition v14)

> **내 PC나 스마트폰을 켜두지 않고, 구글 클라우드의 고속 네트워크와 Google Drive 무손실 영구 연동, Discord 다중 웹훅 리포트로 24시간 무중단 레어 닉네임을 전수검사하는 완벽 가이드입니다.**

---

## 🌟 왜 구글 코랩(Google Colab)인가?
1. **로컬 자원 소모 0% (Zero-Local Footprint)**:
   - 내 컴퓨터나 스마트폰의 CPU, 배터리, 데이터 요금제를 전혀 쓰지 않고 구글 클라우드 인프라를 무료로 활용합니다.
2. **구글 초고속 기가비트 네트워크**:
   - 지연 시간(Latency)이 극도로 낮아 디스코드 API 검사 속도와 처리량(RPS)이 비약적으로 향상됩니다.
3. **Google Drive 실시간 무손실 연동 (Continuous Safe Sync)**:
   - 코랩 세션이 예기치 않게 끊기거나 리셋되어도, **발견된 희귀 닉네임(`available.txt`)은 발견 즉시 Google Drive에 원자적(Atomic)으로 기록**되며, SQLite DB(`d4uc_results.db`)는 30초마다 WAL 체크포인트를 거쳐 안전하게 동기화됩니다.
   - **세션 간 0% 중복 검사**: 새로운 코랩 세션을 열 때 구글 드라이브에 저장된 이전 검사 이력을 자동 복원하므로, 이미 검사한 수만~수십만 개의 닉네임을 다시 검사하는 낭비가 전혀 없습니다.
4. **Discord 다중 웹훅 실시간 모니터링 ("된거" + "안된거")**:
   - **"된거" (AVAILABLE)**: 레어 닉네임 발견 즉시 초록색 임베드와 `@here` 핑으로 알림.
   - **"안된거" & 진행상황 (PROGRESS)**: 5분 주기로 총 검사 수, 사용 중(안된거), 429 레이트리밋, RPS 속도, 구글 드라이브 동기화 상태를 디스코드 채널에 종합 브리핑.
   - **세션 시작/종료**: 클라우드 가동 및 정상 종료 시 최종 백업 통계 알림.
5. **대화형 인터랙티브 폼 (GUI 수준의 편의성)**:
   - 복잡한 리눅스 명령어를 몰라도 마우스 클릭과 슬라이더 조작만으로 모드, 글자수, 워커 수, 웹훅, 구글 드라이브 설정을 완료할 수 있습니다.

```text
https://colab.research.google.com/github/camt4372/Discord-4Character-Usernames-Checker/blob/main/D4UC_Google_Colab.ipynb
```

### 방법 B: 파일 직접 업로드하여 열기

2. [Google Colaboratory](https://colab.research.google.com/)에 접속합니다.
3. 상단 메뉴의 **[파일] -> [노트북 업로드]**를 누르고 `D4UC_Google_Colab.ipynb`를 선택합니다.

## 📋 2. 실행 순서 (단계별 사용법)

노트북에는 총 4개의 실행 셀이 준비되어 있습니다. 순서대로 실행(셀 왼쪽의 ▶ 버튼 클릭 또는 `Shift + Enter`)하시면 됩니다.

---

### [1단계] D4UC 설치 및 환경 준비 (약 30초 소요)
- 셀 왼쪽의 **▶ 실행 버튼**을 누릅니다.
- 구글 코랩 클라우드에 필요한 최신 라이브러리(`curl_cffi`, `rich`, `pyyaml`)와 Linux x86_64 전용 `wireproxy` v1.0.6 바이너리가 자동으로 세팅됩니다.
- `✅ [완료] D4UC 구글 코랩 환경 준비가 100% 완료되었습니다!` 메시지가 뜨면 1단계 성공입니다.

---

### [2단계] 대화형 옵션 설정 (Interactive Form)
오른쪽에 나타나는 폼(Form)에서 마우스로 원하는 조건을 선택합니다:

| 옵션 항목 | 기본값 | 설명 및 권장 설정 |
| :--- | :--- | :--- |
| **`MODE`** | `hybrid` | `hybrid`(하이브리드 추천), `permutation`(순열 전수조사), `dictionary`, `pattern` 등 |
| **`LENGTH`** | `4` | 검사할 사용자명 글자 수 (`3`, `4`, `5` 등) |
| **`WORKERS`** | `5` | 동시 비동기 워커 수 (`5` ~ `10`개 권장) |
| **`SHARD`** | `None` | 다중 창/다중 기기 분할 검사 시 샤딩 선택 (`2_1`, `2_2` 등) |
| **`PROXY_MODE`** | `surfshark` | `surfshark` (1:1 다중 국가 터널 풀) 또는 `direct` |
| **`SURFSHARK_PRIVATE_KEYS`** | `""` | 본인의 Surfshark 와이어가드 개인키 입력 (쉼표 구분 다중 키 입력 가능) |
| **`DISCORD_WEBHOOK_URL`** | `""` | 실시간 발견 알림 및 진행상황 리포트를 수신할 디스코드 웹훅 URL |
| **`WEBHOOK_PROGRESS_REPORT`**| `True` | **체크 권장**: 5분마다 종합 진행상황 ("안된거"/통계) 웹훅 전송 여부 |
| **`WEBHOOK_REPORT_INTERVAL_MIN`**| `5` | 진행상황 리포트 전송 간격 (분 단위, 기본 5분) |
| **`SAVE_TO_GOOGLE_DRIVE`**| `True` | **체크 필수**: 결과를 내 Google Drive에 실시간 및 영구 저장 |
| **`RESTORE_PREVIOUS_HISTORY`**| `True` | **체크 권장**: Google Drive의 이전 DB/결과를 자동 로드하여 중복 검사 0% 방지 |

> **Google Drive 마운트 승인 창이 뜨면**:  
> `Google Drive에 연결` 버튼을 클릭하여 본인 계정으로 권한을 1회 승인해 주시면 됩니다.

---

### [3단계] 실시간 닉네임 검사 가동 (Streaming Runner)
- 셀의 **▶ 실행 버튼**을 누르면 실시간으로 1:1 다중 국가 터널이 연결되고 스트리밍 로그가 출력됩니다.
- **실시간 콘솔 로그 화면 예시**:
```text
======================================================================
🚀 D4UC Google Colab 클라우드 검사를 시작합니다!
======================================================================
[22:25:10] ⚡ [RPS: 12.4] 총: 1,250 | 가용: 0 | 사용중: 1,248 | 429: 0 | 스킵: 2
[22:25:12] ⚡ [RPS: 14.1] 총: 1,280 | 가용: 1 | 사용중: 1,277 | 429: 0 | 스킵: 2
```
- **디스코드 웹훅 알림 동작**:
  - 🚀 **세션 시작 알림**: 탐색 조건(모드, 워커, 샤딩, 드라이브 연동 여부)을 디스코드로 전송.
  - 🟢 **희귀 닉네임 발견 시 ("된거")**: 지체 없이 즉시 초록색 임베드 + `@here` 멘션 전송.
  - 📊 **5분 주기 진행상황 ("안된거")**: 누적 검사 수, 사용 중 닉네임 수, 429 발생 횟수, 실시간 RPS, Google Drive 동기화 상태 종합 리포트 전송.
  - 🛑 **세션 종료 시**: 최종 통계 요약 및 구글 드라이브 보존 확인 전송.
- **작업 중단 방법**:
  - 검사를 멈추고 싶을 때는 언제든 셀 왼쪽의 **정지(■) 버튼**을 누르면, 백그라운드 프로세스가 안전하게 종료(Zero-Zombie)되며 마지막 결과가 Google Drive에 안전하게 최종 동기화됩니다.

---

### [4단계] 발견된 레어 닉네임 확인 및 다운로드
- 지금까지 발견된 `AVAILABLE` 닉네임 목록을 화면에 깔끔하게 출력합니다.
- 동시에 내 로컬 컴퓨터의 다운로드 폴더로 `available.txt` 파일을 원클릭 자동 다운로드합니다.

---

## 🛡️ 3. Google Drive 무손실 동기화 아키텍처 상세

1. **저장 위치**:
   - Google Drive의 `내 드라이브 > D4UC` (`/content/drive/MyDrive/D4UC/`) 폴더 내에 저장됩니다.
   - `available.txt`: 발견된 고유 닉네임 텍스트 파일
   - `d4uc_results.db`: SQLite 전수 검사 이력 데이터베이스
2. **동기화 매커니즘**:
   - `available.txt`: 가용 닉네임 판정 즉시 `os.fsync`를 통한 원자적(Atomic) 직접 추가 기록.
   - `d4uc_results.db`: SQLite WAL 체크포인트를 거쳐 30초마다 안전하게 동기화.
   - 세션 시작 시: 구글 드라이브에 기존 DB가 존재할 경우 로컬 환경으로 즉시 복원(Pre-restore)하여 중복 검사를 0%로 완벽 차단.
   - 세션 종료 시: 안전 종료 훅을 통해 최종 커밋 및 미반영 데이터를 100% 동기화.
